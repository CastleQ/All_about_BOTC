# 홈브류 캐릭터를 만들고 싶은 이야기꾼을 위한 안내서

- 원문: 중국 시계탑에 흐른 피 관련 커뮤니티 (원작자 미상)

---

## 1. 캐릭터의 위상: 스크립트에서의 역할

- 캐릭터 설계의 첫 단계 = 위상 정하기
- 능력 분류표의 "대분류" = 위상 (핵심 역할: 정보 제공 / 죽음 생성 / 보호 등)
- "세부 분류" = 역할 구현 방식 (예: 정보 지속 제공 vs 1회성 제공)

### 1.1. 핵심 능력 우선 설정

- 설계 착수 전 체크리스트
  - 캐릭터 유형: 주민 / 외지인 / 하수인 / 악마 중 선택
  - 위상: (주민이면) 정보 제공 vs 보호 / (하수인이면) 주민 방해 vs 악마 백업
  - 핵심 능력: (정보 제공형 주민이면) 악마 추적용 정보 vs 선량한 플레이어 판별용 정보
- 순서 지키는 이유: 구상의 초점·경계 확보, 막연한 공상에 머무는 상황 방지

### 1.2. 단일 기능 원칙 — "만능캐"의 함정 경계

- 훌륭한 캐릭터 = 대개 단일 기능 특화
  - 독살범: "어떤 주민의 능력이 정상 발동하지 않았을 수 있다"는 논리 제공
  - 부정한 여인: "악마가 다른 곳으로 이동할 수 있다"는 논리 제공
- 초보자 지양 사례
  - 복수 킬 + 악마 중독까지 거는 하수인
  - 보호 + 정보까지 주는 주민
- 공식에도 복합 기능 캐릭터 존재 (과부, 볼톡스 등) — 단, 고도의 게임 이해도 필요 영역
  - 조건: 능력 간 강한 내적 연관성 + 통일된 테마 + 적절한 강도 상·하한
- 초보자의 복합 기능 설계 위험: 능력을 얼기설기 붙인 '프랑켄슈타인' 캐릭터화 → 밸런스 붕괴
- 검증 기준: "이 캐릭터가 스크립트에서 어떤 역할을 하는지 짧고 명확하게 설명 가능한가?" → 불가능하면 설계 실패 가능성 높음
- 예외: 변형 단계·메커니즘 상호작용을 완전히 숙지한 디자이너는 "아이디어 우선 → 포지션 정렬" 방식도 가능
- 초보 단계 권장: 역할 출발형 설계 연습

### 1.3. 초보 디자이너 원칙 — 기초부터

- 신규 메커니즘(빙결, 시간 정지, 기절 등)을 공식 상태(중독, 만취, 광기)급으로 새로 도입 → 비권장
  - 사유: 난이도·위험도 높음, 초보 단계 성공률 낮음
- 권장: 혁신은 기존 시스템 완전 숙달 이후에 시도
- 우선 과제: "제대로 걷는 법" 습득 (곧바로 "날아오르기" 아님)

### 1.4. 소결

- 캐릭터 위상 = 능력 분류표의 대분류 하나를 선택 → 이후 모든 설계·아이디어의 출발 기준점으로 삼기

## 2. 캐릭터 작동과 플레이어 경험

### 2.1. 플레이어 시점에서 사랑받는 캐릭터

- 판단 기준: "내가 플레이어라면 어떤 캐릭터가 나오길 원하는가?"
- 핵심 원칙: 성공적인 캐릭터 = 대다수 플레이어가 기꺼이 받아들이고 직접 플레이하고 싶어 하는 캐릭터
  - 반증: 설계자 본인이 테스트 시 재미없고 다시 하기 싫다면 → 커뮤니티 인정 불가능

**매력 요소 6축**

| 축 | 설명 | 예시 |
| --- | --- | --- |
| 위력 | 게임 결과에 눈에 띄는 영향, "내가 캐리했다" 성취감 | 퇴마사, 점쟁이, 독살범, 늑대인간, 대신 |
| 영향력 | 판의 중심이 되는 느낌, 시선 집중 | 아가씨, 이교도, 고블린, 씨이코패스 |
| 자유도 | 고정되지 않은 플레이 방식, 창의적 연기 유도, 재플레이 가치 높음 | 철학자, 식인종, 기억상실자, 정치인, 예술가, 마귀할멈 |
| 정보력 | 정보 우위를 통한 안정감·계획 능력 부여 | 서번트, 몽상가, 스파이, 과부 |
| 상호작용성 | 다른 플레이어와의 빈번한 상호작용 강제·유도 | 메제펠레스, 험담가, 곡예사, 마술사, 교주, 대사제 |
| 독창성 | 드물거나 '간지 나는' 설정·능력 | 양귀비 재배자, 무신론자, 연금술사, 마법사 |

**기피 요소 — "깍두기 캐릭터"**

- 특징: 능력 약함 + 정보량 적음 + 판세 영향 미미
- 결과: 참여감 저하, 게임에 끌려가는 느낌
- 예시
  - 상호작용 거의 없는 "알고 시작합니다"형 정보 주민 (요리사, 시계공 등)
  - 메커니즘 피드백 거의 없는 주민 (군인, 시장, 평화주의자 등)
  - 메커니즘 피드백 거의 없는 외지인 (은둔자, 땜장이 등)
- 예외적 필요성: 일부 캐릭터는 스크립트 내 "논리 보완"/"기능 보완" 역할 담당 (은둔자, 군인, 땜장이, 평화주의자 등)
- 설계자 대응: 이런 '수동적' 캐릭터에도 메커니즘·서사 측면에서 재미 요소 추가 → '할 일 없는 느낌' 완화

### 2.2. 사례 비교 — 재미있는 설계 vs 투박한 설계

**사례 1: 세탁부 vs 반려자**

> [세탁부] 플레이어 2명 중 1명이 특정 마을 주민이라는 걸 알고 시작합니다.

> [반려자] 첫날 낮, 공개적으로 플레이어 1명을 선택할 수 있습니다. 그랬다면 이야기꾼에게 찾아가 서로의 캐릭터를 공개합니다. 상대방이 거짓말을 했다면, 비밀리에 이 사실을 알게 됩니다.

- 기본 기능 동일: 선한 플레이어 1명 + 캐릭터 특정 정보 제공
- 메커니즘 차이
  - 세탁부: 밤에 수동적 정보 수신, 악한 진영 방해 수단 거의 없음
  - 반려자: 낮에 능동적 대상 선택, 악한 진영이 대상 강탈·거짓말로 방해·역이용 가능
- 상호작용 차이
  - 세탁부: 속닥임 선택 사항 → 초반 침묵·추측으로 흐르기 쉬움
  - 반려자: 첫날 낮 공개 필수, 발화 자체가 "발사 신호"로 작용 → 고강도 상호작용 유발, 사회적 이벤트 창출

**사례 2: 야경단원 vs 조향사**

> [야경단원] 게임당 한 번, 밤에 플레이어를 1명 선택할 수 있습니다. 해당 플레이어는 당신이 누구인지 알게 됩니다.

> [조향사] 게임당 한 번, 밤에 플레이어를 1명 또는 악한 캐릭터를 1개 선택할 수 있습니다. 해당 플레이어는 조향사가 참가 중이라는 것을 알게 됩니다.

- 메커니즘 차이
  - 야경단원: 자기 선함 증명 기능 위주, 추가 기능 거의 없음
  - 조향사: 대상 비공개 → 직접 증명력은 약화, 대신 악한 진영에 심리적 압박 부여 (선택된 대상 여부 불명 → 공개 판단 곤란)
- 상호작용 차이
  - 야경단원: 평이한 신뢰 기반 1:1 협력 커뮤니케이션
  - 조향사: 자기 노출 최소화, 악측에 "공개해야 하나?" 고민 유발 → 논리 추리를 심리전·블러핑으로 확장

**사례 3: 땜장이 vs 규수**

> [땜장이] 당신은 언제든지 죽을 수도 있습니다.

> [규수] 처음으로 죽게 될 때, 대신 살아있는 플레이어 2명이 죽을 수도 있습니다.

- 공통점: 추가 죽음 정보 공급 외지인
- 메커니즘 차이
  - 땜장이: 이야기꾼 임의 시점 사망, 상호작용 불필요, 랜덤 변수로 리듬 조절
  - 규수: 타 플레이어 행동(처형·악마 공격)에 능력 발동 연동
- 상호작용 차이
  - 땜장이: 수동적 압박 체험
  - 규수: 협박·거래의 중심 ("처형하면 두 명 데려간다" 등 능동적 협상)
- 결론: 동일 포지션이라도 설계에 따라 '수동적 압박' ↔ '능동적 협상·공포 조성'으로 체험 차별화 가능

### 2.3. 새로운 설계 각도 확보법

**사고 1: 능력의 핵심 목표 전환**

- 방법: 능력 형식 유지 + 노리는 목표·체험 변경 → 기존 공식 캐릭터와 유사성 회피
- 예시: 복수 킬 악마 변형
  - 기존 모델(샤발롯 등) 목표: "효율" (다수 처치로 처형 기회 압축)
  - 변형 방향: 선한 진영에 '추적 단서' 제공하는 기믹으로 전환
  - 적용 예 — 아서 왕(악마)
    > 매일 밤*, 플레이어를 1명 선택합니다. 해당 플레이어는 죽습니다. 게임당 한 번, 하수인을 죽이면, 해당 하수인은 당신과 캐릭터를 맞바꾸고, 대신 다른 플레이어 2명이 죽습니다.
  - 효과: 단순 킬 효율 상승이 아닌 자리 바꿔치기 + 다중 사망 → 선한 진영에 단서 제공 ("다중 사망 = 왕위 교체?" 추론 유도)

**사고 2: 핵심 메커니즘의 타 유형 이식**

- 방법: 특정 캐릭터의 상징적 메커니즘을 다른 캐릭터 유형으로 옮겨 재구성·밸런싱
- 예1: 열기구 조종사(구버전)의 지연 정보 메커니즘 → 트리거 능력 주민에 이식
  - 특정 조건(사망·처형 등) 충족 시 강력한 정보 일괄 제공 → "트리거 능력은 약하다"는 문제 보완
- 예2: 마귀할멈의 '캐릭터 변경' 메커니즘 → 타 유형 이식
  - 악마가 밤마다 캐릭터 변경 → 추적 교란
  - 외지인이 조건부 캐릭터 변경 → 생존/방해 기회 획득
  - 적용 예 — 공중곡예사(주민)
    > 당신이 죽으면, 모든 캐릭터 유형의 플레이어를 1명씩 알게 됩니다. 만약 선한 플레이어의 능력 또는 처형으로 죽었다면, 당신은 취합니다.
  - 특징: 강력한 트리거 능력 + 사망 조건별 위압·협상 요소 결합

### 2.4. 소결

- 캐릭터 플레이 설계 핵심: 매력 포인트 선정 (위력/영향력/자유도/정보력/상호작용성/독창성)
- 재미 향상 3요소: 플레이어 능동성 ↑ / 선택 폭 ↑ / 상호작용 깊이 ↑
- 새 아이디어 출처: 기존 설계의 관찰·분해·재구성 (즉흥적 발상 아님)

## 3. 수치 설계: 캐릭터 밸런스와 변형 단계

- 전제: 사회적 발언이 핵심 게임이지만, 변형 단계 이해도 중요
- 일반 플레이어/공식 스크립트 사용자: 변형 단계 몰라도 무방
- 직접 스크립트·오리지널 캐릭터 설계자: 변형 단계 이해 필수

**변형 단계 정의**

- 특정 능력(예: "선한 플레이어 1명을 아는 능력")의 가장 표준적·단순한 최초 형태
- 이후 유사 능력 설계 시 이 표준형을 기준으로 강화/약화 요소를 조합 → 강도는 유사하되 플레이 감각이 다른 변형 창출
- 능력 분류별로 매우 다양 → 전량 나열 불가, 모델 예시만 제공 (그대로 모방보다 소화·재구성 권장)

### 3.1. "선한 플레이어 1명을 아는 한정된 정보의 주민" — 예시 비교

- 표준 모델: 관리인
  > 선한 플레이어 1명을 알고 시작합니다.
- 비표준 1: 세탁부
  > 플레이어 2명 중 1명이 특정 마을 주민이라는 걸 알고 시작합니다.
  - 변형: 대상 1명 → "2명 중 1명 + 캐릭터"로 정밀도↑, 불확실성↑
- 비표준 2: 할머니
  > 선한 플레이어 1명과 그 캐릭터를 알고 시작합니다. 악마가 해당 플레이어를 죽이면 당신도 죽습니다.
  - 변형: 정보 정확도↑ + 추가 죽음 리스크 부과
- 비표준 3: 픽시
  > 게임에 참가 중인 주민 캐릭터 1개를 알고 시작합니다. 만약 당신이 그 캐릭터라고 "광기"했다면, 해당 캐릭터의 플레이어가 죽고 나서 그 캐릭터의 능력을 얻을 수도 있습니다.
  - 변형: 정확성 일부 포기 + 추가 보상(능력 획득) 부여
- 비표준 4: 야경단원
  > 게임당 한 번, 밤에 플레이어를 1명 선택할 수 있습니다. 해당 플레이어는 당신이 누구인지 알게 됩니다.
  - 변형: 발상 전환 ("내가 안다" → "상대가 나를 안다")

- 추가 설계 예시
  - 화가 (예1)
    > 참가 중인 캐릭터 1개를 알고 시작합니다. 매일 낮, 한 번, 해당 캐릭터의 플레이어를 추측할 수 있습니다. 맞다면, 그날 밤 또 다른 캐릭터를 알게 됩니다.
  - 반려자 (예2, 2.2절 재인용)
  - 조향사 (예3, 2.2절 재인용)

### 3.2. "악한 플레이어 1명을 아는 한정된 정보의 주민" — 예시 비교

- 전제: "선 정보" < "악 정보" 가치, "악마 정보" > "하수인 정보" 가치 (비대칭 대립 구조)
- 표준 모델(필자 기준): "2명 중 1명이 악한 진영이다" 수준 (공식에 정확 부합 캐릭터는 없음)
- 비표준 1: 조사관
  > 플레이어 2명 중 1명이 특정 하수인이라는 걸 알고 시작합니다.
  - 특징: 악마 불명, 하수인 캐릭터 특정 가능
- 비표준 2: 슈겐자
  > 가장 가까운 악한 플레이어가 시계 방향인지 반시계 방향인지 알고 시작합니다. 거리가 같다면 이 정보는 임의적입니다.
  - 특징: 정보 흐릿하지만 악 진영 범위 1~4명으로 축소, 반대 방향 선 진영 묶기 가능
- 비표준 3: 귀족
  > 플레이어 3명을 알고 시작합니다. 그중 1명은 악한 진영입니다.
  - 특징: 3명 중 1악 2선 구조, 1명 특정 시 나머지 2명 자동 확정
- 비표준 4: 현상금 사냥꾼
  > 악한 플레이어 1명을 알고 시작합니다. 알고 있는 플레이어가 죽으면, 밤에 또 다른 악한 플레이어를 알게 됩니다. [주민 중 1명은 악한 진영입니다.]
  - 특징: 매우 강력 + 부작용 극대화, 지속 정보처럼 보이나 실제로는 보상 결합형 한정 정보
- 비표준 5: 재봉사
  > 게임당 한 번, 밤에 본인을 제외하고 플레이어 2명을 선택할 수 있습니다. 해당 플레이어들이 같은 진영인지 알게 됩니다.
  - 특징: 선악 직접 미공개, 플레이어 자체 논리 조합 유도
- 결론: 해당 모델은 설계 여지 다수 잔존 → 직접 파생 설계 연습 권장

### 3.3. 변형 단계 활용법: 관찰 → 귀납 → 적용

1. 관찰: 레퍼런스 수집
2. 귀납: 핵심 공통점 추출
3. 적용: 모델 내 창의적 변형

- 예
  - 신규 다중 사망 악마 설계 시: 샤발롯, 포, 야가바블 분석
  - 취하게 만드는 외지인 설계 시: 주정뱅이, 퍼즐마스터, 연인 분석
- 절차: 공통점 정리 → "표준 모델" 확립 → 소폭 이탈 설계 → 밸런스 유지 + 새로움 확보

### 3.4. 소결

- 변형 단계 기준 설계 = 캐릭터 밸런스 유지 핵심
- 절차: 공식 캐릭터 관찰 → 공통점 추출 → 모델 내 강약·제약·보상 조정
- 효과: 과강/과약/정체불명 캐릭터 방지

## 4. '시계탑 언어': 공식처럼 보이는 능력 문장 작성법

- 전제: 능력 텍스트에도 구어체/문어체 같은 규범·습관 존재
- 좋은 문장: 간결·명료·모호함 없음 / 나쁜 문장: 장황·애매·해석 분쟁 유발

### 4.1. 최우선 원칙 — 명료성, 오해 불가

- 필수 요소: 주체/대상/행동 명확화 (언제·누가·무엇을·누구에게·어떤 효과)
- 예시
  - 나쁜 예: "1명을 죽일 수 있다." → 누가/언제/어떤 조건인지 불명
  - 좋은 예: "매일 밤*, 플레이어를 1명 선택합니다. 해당 플레이어는 죽습니다."
- 용어 통일 필수: "죽는다/제거된다/사라진다" 등 혼용 금지, 하나로 고정
- 시점 명확화 필수: "밤에 알 수 있다" (X, 어느 밤인지 불명) → "알고 시작합니다" / "매일 밤" (O)

### 4.2. 구조 원칙 — 간결·논리적 서술

- 표준 순서: 시점 → 행동 → 효과(및 지속 시간)
- 예시
  > 매일 밤, 플레이어를 1명 선택합니다. 해당 플레이어는 다음 황혼까지 중독됩니다.

  > 매일 낮, 지명 전에 플레이어 1명을 선택할 수 있습니다. 해당 플레이어는 오늘 처형될 수 없습니다.
- 원칙: 핵심 메커니즘 선기술 → 예외/조건 후기술

### 4.3. 기능 원칙 — 범위·상태 명확화

- 대상 범위 명시 필수 표현: "당신", "당신을 제외한 플레이어", "이웃(플레이어)", "살아있는 플레이어", "죽은 플레이어" 등
- 예시
  > 매일 밤, 살아있는 플레이어 중 이웃한 2명을 선택합니다. 해당 플레이어들이 같은 진영인지 알게 됩니다.

### 4.4. '시계탑 언어' 체크리스트

- 누가/언제/무엇을/누구에게/어떤 효과인지 전부 드러나는가?
- 더 짧게 쓸 수 있는가? 중복 표현 없는가?
- 유사 공식 캐릭터와 용어·문장 구조 일관적인가?
- "시점 → 행동 → 효과" 순서를 따르는가?
- 경계 상황(마지막 날, 미참여 시, 취함·중독 등) 고려했는가?
- 1~2회 열람으로 핵심 메커니즘 이해 가능한가?

### 4.5. 소결

- 능력 텍스트 원칙: 간결·명료·논리적, "시점-행동-효과" 구조 + 용어 통일

## 5. 상호작용 설계를 통한 캐릭터의 사회적 속성 강화

- 전제: 게임 본질 = 사회적 추리 게임 (신뢰·속임수·협력·배신), 상호작용 대부분 낮에 발생
- 고급 설계 과제: "능력으로 낮 시간 상호작용의 빈도·깊이를 어떻게 늘릴 것인가"
- 적용 범위: 홈브류 + 향후 공식 캐릭터 발전 방향 공통

### 5.1. 사례 1: 신문 배달 소년(주민) — 공통 화제로 초반 침묵 타파

> 매일 낮, 이야기꾼에게 '뉴스' 하나를 비밀리에 들을 수 있습니다. 만약 그 '뉴스'를 공개적으로 말했다면, 다음 밤에 그것이 사실인지 알게 됩니다.

- 효과
  - 첫날부터 화제 생성 강제 ("오늘의 뉴스는...")
  - '뉴스' 서사화로 정보의 발화 유인 증가
  - 타 플레이어의 모방/가짜 뉴스 생성 → 대화·연기·의심 촉발

### 5.2. 사례 2: 고양이 탐험대(주민) — 소외 플레이어 참여 유도, 집단 결정 창출

> 매일 낮, '탐험'한 적 없는 살아있는 플레이어 1명은 공개적으로 탐험하겠다고 선언할 수 있습니다. 해당 플레이어가 다음 밤에 살아남는다면, 당신은 해당 플레이어와 다른 진영인 플레이어를 1명 알게 됩니다.

- 효과
  - 상호작용 무대를 자신 → 전체 플레이어로 확장
  - 정보 부족/저비중 플레이어에게도 기여 기회 제공
  - 캐릭터 부재 상황에서도 "누구를 탐험 보낼까" 논의 유발 가능

### 5.3. 사례 3: 지옥의 방랑자(외지인) — 진영 대립 격화, 클라이맥스 생성

> 매일 낮, 지명 전에, 하수인은 공개적으로 지옥의 방랑자를 '옹립'할 수 있습니다. 그랬다면, 당신은 악마와 진영 및 캐릭터를 바꾸고, 그 후 해당 플레이어는 취합니다.

- 효과
  - 하수인의 공개 '옹립' 자체가 극적 이벤트
  - "정말 방랑자가 있는가?", "악마가 바뀌었는가?" 질문 폭발 → 심리전 절정 유도

### 5.4. 사례 4: 스핑크스(하수인) — 독특한 체험과 긴장 조성

> 매일 밤, 플레이어를 1명 선택할 수 있습니다. 다음 날 처형 단계에서, 이야기꾼은 먼저 해당 플레이어를 지목하고, 예/아니오로 대답할 수 있는 질문 1개를 물어봅니다. 틀렸다면, 해당 플레이어는 처형될 수도 있습니다.

- 특징: 이야기꾼 의존도 높음
- 효과: "질문으로 목숨이 걸리는 순간" → 강한 기억점 제공

### 5.5. 소결

- 좋은 상호작용 디자인 4요소
  - 공통 화제 창출 (신문 배달 소년)
  - 폭넓은 참여 촉진 (고양이 탐험대)
  - 극적 이벤트 창출 (지옥의 방랑자)
  - 독특한 경험 제공 (스핑크스)
- 결론: 사회적 상호작용 = 시계탑의 핵심
- 방향성: "혼자 정보 캐기"/"순수 능력 싸움" 탈피 → "캐릭터를 사회적 촉매제로 설계"

## 6. 서사 디자인: 캐릭터에 생명과 긴장 부여

- 전제: 좋은 캐릭터 = 메커니즘 + 서사의 결합. 배경 서사는 몰입감·설득력·기억성 강화

### 6.1. 서사-메커니즘 정합성

- 원칙: 능력은 인물다워야 함, 배경과 능력이 상호 설명되어야 함
- 예: 군인 — 배경("수많은 전장, 쉽게 죽지 않음") = 능력("악마의 능력이 통하지 않는다") 일치
- 반례: "방 청소하는 하녀" + "매일 밤 1명을 죽이는 능력" → 어색
  - 대안: "매일 밤 일어난 사람을 감지한다" (자연스러움 확보)

### 6.2. 키워드로 세계관 구축 (초보 주의)

- 키워드 = 능력 축약 명칭 + 메커니즘-서사 연결 다리
- 예시
  - "교주 – 교단에 가입" → 특수 승리 조건의 종교적 표현
  - "샤발롯 – 뱉어내다" → 부활 메커니즘의 흉포한 짐승 표현
  - "어부 – 조언" → 정보 제공의 상호작용화
  - "릴몬스타 – 돌보기" → 보호 메커니즘의 부모-아이 관계화
- 권장: 초보자는 신규 키워드 남발보다 기존 공식 키워드 활용

### 6.3. "할 수 있는 것"보다 "하고 싶어 하는 것" 설계

- 원칙: 능력(할 수 있음)뿐 아니라 동기(하고 싶어 함)도 설계 필요
- 예
  - 능력: "네 이웃 플레이어가 죽으면, 그날 밤에 일어나 하수인을 죽일 수 있다"
  - 동기: "원한 맺힌 자를 위해 하수인을 사냥하는 복수귀"
- 효과: 기능을 넘어선 '연극 욕구' 자극

### 6.4. 사례: 지옥의 방랑자 서사 완성

- 배경: 원래 악한 진영 소속 → 추방·봉인 상태로 선한 진영에 낙하 → 하수인의 '옹립'으로 악마 복귀 가능
- 플레이버 텍스트 예시
  > "그들은 내 날개를 잘라내고 나를 황무지에 던졌다. 이 썩은 흙의 모든 톱니바퀴가, 지옥이 새 왕을 맞이하는 날을 세고 있다."
- 효과: 동일 능력도 "정치적 쿠데타"처럼 인상 깊게 인지됨

### 6.5. 소결

- 서사 디자인 = 캐릭터에 영혼 부여
- 구성 요소: 메커니즘과 맞물리는 배경 + 적절한 키워드 + 내적 동기

## 7. 이름 짓기: 네이밍 제안

- 전제: 이름 = 캐릭터의 이미지·위상·능력 대략치를 즉각 전달하는 핵심 요소
- 공식 디자인 틀 준수 + 세계관 일관성 유지 → 완성도 향상 (필수는 아니나 권장)

### 7.1. 주민·외지인 — 평범함 속 현실성과 기이함

- 공통 원칙: 일상 뿌리 또는 민간 설화 기원, 구체적 사회적 캐릭터/익숙한 판타지 생물 연상
- 추천
  - 직업·신분: 요리사, 서기관, 수도승, 향신료 상인, 선장
  - 관계·호칭: 할머니, 연인, 고아, 방탕아, 부랑자, 스승
  - 인간형 생물·요정: 밴시, 엘프, 선녀, 산신령, 팅커벨
- 비추천
  - 구체적 사람 이름 (저스틴, 빅터 등) — 중세 판타지 분위기 저해
  - 추상적 명칭 (서리의 심장, 희망, 대포 등) — 칭호/사물화, 감정 이입 저해

### 7.2. 하수인 — 급이 낮은 악마와 악마의 하수인

- 공통 원칙: 종속성·음모성·비-최종보스 위치 표현, 의존성·유혹·저위 위협감 반영
- 추천
  - 사악한 직업·칭호: 스파이, 사기꾼, 심문관
  - 부정적 의미 명칭: 비방꾼, 찬탈자, 역병 의사
  - 전통 하급 괴물: 고블린, 하피, 구울, 데미안
- 비추천
  - 최상위 존재의 이름 (옥황상제, 제우스, 티폰 등) — 위압감 과다, 힘의 계층감 붕괴

### 7.3. 악마 — 공포의 근원, 이야기의 중심

- 공통 원칙: 최종 보스·궁극적 위협·고대성·사악함 전달
- 추천
  - 신화 속 유명 괴물: 레비아탄, 케르베로스, 나가, 펜리르
  - 악마 변주형 이름: 노스페라투(흡혈귀 시조), 사마엘(타락한 천사), 라미아(흡혈 마녀)
  - 고퀄 창작 이름: 팡구, 카잘리, 샤발롯, 즈낙 (무게감 있는 음절 조합, 불길한 어감)
  - 이름-능력 연계: 순서대로 죽이는 악마 → 조디온 / 사망자 발언 금지 악마 → 파령철추 / 공포·절망 전파 악마 → 기어다니는 공포

### 7.4. 소결

- 주민·외지인: 생활·전설 기반 이름
- 하수인: '악마의 부하'다운 느낌
- 악마: 대본 전체의 간판, 고대적·파괴적 기운
- 공통 회피 대상: 인명, 추상 개념, 과도한 신격 이름 (세계관 일관성 저해)

## 8. 아이콘과 아트워크: 스크립트의 첫인상

- 아트워크 = 플레이어가 스크립트를 접할 때 가장 먼저 느끼는 품질 요소
- 권장: 전문 일러스트레이터 협업
- 최소 기준: 아이콘·표지·배경 등 전체 스타일 통일
- 위험: 이미지 중구난방 사용 시 완성도·신뢰감 저하

## 9. 테스트와 다듬기: 설계에서 완성으로

- 전제: 능력 텍스트·설정 작성 = 완료가 아님
- 필요 절차: 여러 버전 문장 비교 → 3판 이상 실전 테스트 → 구조적 피드백 수집 → 수정 → 재테스트 (순환)
- 완료 후 추가 문서화 필요: 플레이 가이드, 대응법, 상황 예시 등 → 완전한 캐릭터 패키지 구성

### 9.1. 다듬기 실례 — 캐릭터 '발키리'

- 목표: 가장 간결·명확·오해 최소인 표현 탐색
- 초안 버전 목록
  - 매일 밤*, 모든 죽음은 당신의 허락 없이 일어나지 않습니다. 만약 허락하지 않았다면, 오늘 밤에는 오직 당신만 죽습니다.
  - 매일 밤*, 당신은 그날 밤에 죽을 플레이어를 알게 되며, 해당 플레이어들을 살릴 수 있지만, 당신은 죽습니다.
  - 매일 밤*, 당신은 죽기로 결정할 수 있습니다. 그랬다면, 그날 밤에는 다른 누구도 죽지 않습니다.
  - 매일 밤*, 누군가 죽게 될 때마다 일어나 죽을 플레이어가 누구인지 알게 됩니다. 그리고 해당 플레이어 대신 죽을지 선택합니다.
  - 매일 밤*, 죽을 플레이어를 알게 됩니다. 해당 플레이어들을 부활시키고 취하게 만들 수 있지만 당신은 죽습니다.
  - 매일 밤*, 플레이어를 아무렇게나 선택합니다. 그날 밤, 해당 플레이어들이 죽을 때 당신이 대신 죽습니다. 그날 밤 당신이 먼저 죽어도 이 능력은 유지됩니다.
  - 첫날 밤, 플레이어를 아무렇게나 선택합니다. 매일 밤, 해당 플레이어들이 죽게 될 때 일어나 대신 죽을지 선택합니다.
  - 매일 밤*, 모든 죽음은 당신의 행동 이후로 연기됩니다. 당신은 누가 죽을지 알게 되고 해당 플레이어들 대신 죽을지 선택합니다.
  - 매일 밤*, 모든 죽음은 당신이 사망자 명부에 동의한 후에만 일어납니다. 동의하지 않으면, 그날 밤에는 오직 당신만 죽습니다.
- 최종안 — 발키리(주민)
  > 매일 밤*, 모든 죽음은 당신이 사망자 명부에 동의한 후에만 일어납니다. 동의하지 않으면, 그날 밤에는 오직 당신만 죽습니다.
- 비교 의의: 문장 미세 차이 → 이해 난이도 / 상호작용 범위 / 이야기꾼 진행 난이도 / 능력 상·하한에 직접 영향

### 9.2. 실전 검증 절차

1. 테스트 환경 세팅
   - 성숙하고 위치가 맞는 기존 스크립트 선정
   - 기능·슬롯 겹치는 기존 캐릭터 1개 제거 후 신규 캐릭터 투입
   - 목적: 기본 균형 유지 + 신규 캐릭터 특성 확인
2. 테스트 판수 확보
   - 최소 3판 이상 유효 테스트 권장
   - 포함 권장 상황
     - 정상 작동 판
     - 악한 진영 위장 캐릭터로 사용된 판
     - 초반 탈락 → 간접 영향만 남는 판
3. 구조적 피드백 수집
   - 플레이어 질문 예시: 능력 텍스트 이해도 / 체감 위력(강함·약함·적당) / 재미 여부(성취감 vs 무력감·혼란)
   - 이야기꾼 질문 예시: 진행 난이도·절차 명확성 / 변형 단계 평가 / 조정 방향 제안
4. 설계자 자체 정리
   - 실전 문제점 기록
   - 능력 안정성 vs 판별 변동성 평가
   - 상호작용 촉진 여부 vs 교착·혼란 유발 여부 점검

### 9.3. 반복 개선

- 수정 범주
  - 변형 단계 조정: 제약 추가/완화
  - 명확성 개선: 오해 소지 문장 재작성, 용어·시점 정리
  - 체험 개선: 상호작용 증대 또는 좌절감 완화 방향 미세 조정
- 절차: 수정 → 재테스트 → 재피드백 → 재수정 (설계자 만족 시까지 반복)
- 완성 후 추가 문서화 항목: 규칙 세부 설명 / 알림 토큰 설계 / 이야기꾼 운영 가이드 / 플레이 예시 / 담당 플레이어용 팁 / 상대 플레이어용 팁

### 9.4. 소결

- 테스트·다듬기 = 설계를 '성숙한 캐릭터'로 전환하는 필수 과정
- 절차 요약: 문장 버전 비교·최적화 → 구조화된 실전 테스트로 피드백 수집 → 순환적 수정
- 목표: 밸런스·재미·이해도를 모두 갖춘 캐릭터 완성
