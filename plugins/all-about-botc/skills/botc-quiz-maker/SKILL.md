# 시계피 이야기꾼 퀴즈 출제

숙련 이야기꾼을 위한 룰 판정 퀴즈를 만든다. 번역 위키의 이야기꾼 퀴즈(https://castleq.github.io/botc-wiki-ko/quiz.html)와 같은 형식으로, 문제 화면의 마도서를 보고 상황을 파악하게 한다.

## 공통 원칙

- 같은 플러그인의 `botc-rules-advisor` 스킬 `references/운영방침.md`를 따른다(0장 불변 규칙, 1장 용어·육하원칙). 위치: 이 스킬 폴더의 형제 폴더 `../botc-rules-advisor/references/`, 없으면 `find / -type f -path '*botc-rules-advisor/references/운영방침.md' 2>/dev/null | head -1`로 찾는다.
- 모든 정답은 번역 위키 캐릭터 파일(`references/wiki/`)의 `## 요약`·`## 진행 방법`·`## 예시`, 용어집, 룰북, `기타예외규칙.md`의 공식 답변 중 하나로 **출처를 댈 수 있어야** 한다. 근거를 댈 수 없는 문항은 만들지 않는다.

## 출제 기준

1. **정답이 하나로 정해지는 문제만** 낸다. 징크스나 이야기꾼의 해석·재량에 따라 답이 갈리는 문제는 내지 않는다.
2. 수백~수천 판에 한 번 나올 극단 상황이나, 어떤 이야기꾼도 택하지 않을 결정을 묻는 문제는 내지 않는다.
3. 문항마다 **주연 캐릭터와 판정 원리가 최대한 겹치지 않게** 한다. 같은 원인의 취함을 두 번 다루지 않는다. 다른 원인의 취함·중독이거나, 같은 캐릭터라도 묻는 원리가 다르면 괜찮다.
4. 능력문의 "처형 / 처형으로 사망 / 사망 / 밤에 사망" 구분처럼 숙련자에게 쉬운 함정은 내지 않는다.
5. 오답 보기는 실제로 이야기꾼이 저지르기 쉬운 오해(흔한 오해, 넓혀 읽은 문구 등)로 만든다.

## 문항 형식

- **시점**: 문제 화면의 마도서가 이야기꾼에게 보이는 순간. 문제 글에는 **마도서로 알 수 없는 정보**(며칠째인지, 밤/낮, 밤 순서 위치, 그날 낮에 있었던 일)만 적는다.
- **인원·구성**: 주민/외지인/하수인/악마 순. 셋업 비율을 바꾸는 캐릭터가 있으면 반영한 값. 게임 도중 캐릭터가 바뀐 플레이어는 원래 캐릭터로 셋업 수를 맞춘다. 공식 인원 구성표와 반드시 맞춘다.
- **마도서 셋팅**: 좌석은 시계 방향 순서. 진영이 토큰 기본 진영과 다르면 굵게 표시(토큰을 뒤집어 놓는 경우).
- **처리 전/후**: 마도서가 정답을 드러내는 문제는 문제 화면(처리 전)과 해설 화면(처리 후)을 따로 두고, 해설 화면 표 마지막 열 '변화'에 바뀐 점(캐릭터 변경·진영 전환·사망/부활·알림 토큰 추가/제거)을 적는다.
- **마도서 가운데**: 플레이어 자리에 놓이지 않는 토큰(예: 이야기꾼이 얻은 능력)은 따로 적는다.
- **복수 정답**: "모두 고르세요" 문항은 정답을 모두 고르고 오답을 하나도 고르지 않아야 정답(부분 점수 없음). 정답이 하나뿐인 "모두 고르세요"도 함정으로 쓸 수 있다.
- 출제 전에 셋팅 자체가 다른 판정을 끌어들이지 않는지 점검한다. 예: 정답과 무관한 중독원이 주인공 캐릭터를 건드릴 수 있는 배치, 인원 구성과 충돌하는 캐릭터 조합, 공식 징크스가 걸린 조합.

## 문항 양식 (복사해서 사용)

```markdown
## N번 — 캐릭터A × 캐릭터B

### 문항 정보

- **시점**: (예: 셋째 날 밤, ○○ 차례 직전)
- **스크립트 기반**: (예: 점철되는 혼란 / 커스텀 (○○ + ○○))
- **인원·구성**: (예: 9인 기본 5/2/1/1)
- **문제**: (마도서로 알 수 없는 정보만)
  1. 보기
  2. 보기  ✅ 정답
  3. 보기
  4. 보기

### 마도서 셋팅 — 문제 화면 (처리 전)

| 좌석 | 이름 | 캐릭터 | 유형 | 진영 | 상태 | 알림 토큰 |
|---|---|---|---|---|---|---|
| 1 | | | | | 생존 | — |

### 마도서 셋팅 — 해설 화면 (처리 후)  ← 필요할 때만

| 좌석 | 이름 | 캐릭터 | 유형 | 진영 | 상태 | 알림 토큰 | 변화 |
|---|---|---|---|---|---|---|---|
| 1 | | | | | | | **사망** |

### 해설

(왜 정답인지, 오답 보기는 어떤 오해인지)

### 근거

- [캐릭터명](https://castleq.github.io/botc-wiki-ko/c/<id>.html) — 요약 N / 진행 방법 / 예시 N
- 용어집 '항목명' / `기타예외규칙.md` N번
```

## 퀴즈 데이터(json)로 옮길 때

웹 퀴즈로 만들 경우 문항별로 아래처럼 대응시킨다.

| 문항 md | json |
|---|---|
| 문제 화면 마도서 | `players` |
| 해설 화면 마도서 | `playersAfter` (있을 때만) |
| 마도서 가운데 토큰 | `center`: `[{token, reminders}]` |
| 굵게 표시한 진영 | `flipped: true` |
| 복수 정답 | `multi: true`, `a`는 정답 번호 배열(0부터), 채점은 `scoring: "exact"` |
